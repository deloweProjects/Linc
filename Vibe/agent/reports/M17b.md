## 1. PART A — the decision, twice, provable with no network

explicitly: **malformed or missing input degrades to `None`, never `Forced`**, and **`Forced` ignores `skipped`
unconditionally** — a skip must not become a permanent opt-out of a security floor.

Tested by **`tools/updatesim`** (new) and the Android `UpdateDecisionTest`. I added `updatesim` because no existing
harness covers version arithmetic, and the three production files carry no WinUI types specifically so it can

## 2. PART B — fetch, store, show
**B1 — the manifest shape, verbatim, as the owner will implement it.** A static file, plain GET. It is documented in the
same words in `UpdateManifest.cs`'s doc comment.
```json
{
  "latest": "1.2.0",
  "minimumSupported": "1.1.0",
  "url": "https://example.com/Linc-1.2.0.exe",
  "notes": "one short line",
  "sha256": "hex sha256 of the file at url"
}
```
Every field is nullable on purpose; parsing is case-insensitive; a partial or malformed manifest returns null and the
caller does nothing. The phone's manifest is the same shape, with `url` pointing at an APK.

**B2 — where the URL lives.** Desktop: `UpdateManifestUrl` (+ `SkippedUpdateVersion`) appended to `DeviceRegistry`'s
`Settings` record with the same trailing-nullable posture as `StartWithWindows`, so an older `settings.json` still
deserializes; shown as an "Updates" card on the Settings page. Phone: `UpdateSettings` over the existing `linc`
SharedPreferences, shown as an "Updates" `LincCard` in `SettingsScreen.kt`. **On both sides blank stores null** —
"cleared" and "never set" are the same inert state.

**B3 — when it checks.** `AppShellViewModel`'s constructor fires `CheckForUpdatesAsync()` **fire-and-forget after the UI
is up**; it never blocks launch. It lives in the shell rather than a page for the standing reason (GUARDRAILS): a page
view model is lazy, so an update the user must take would never be offered. The gate is `MinimumInterval = 6 h` plus an
in-flight flag and a `SemaphoreSlim(1,1)`. Failures are caught and logged once, never surfaced.

**B4 — what the user sees.** Desktop (`MainWindow.xaml`, M14's card style): Optional is a dismissible card in the banner
slot with the version, the note, *Update* and *Skip this version*; Forced is a full overlay (`Grid.RowSpan=3`) with one
sentence and *Update*, **no dismiss**. Phone (`ui/UpdateUi.kt`, M17a's `LincCard`/`Dimens`): the same two shapes. **Both
Forced surfaces block the app's function, not the process** — the desktop title bar, close button and tray menu stay
live; the phone screen is an ordinary composable, so Back and the launcher behave normally. Each says so on screen.
Every `Visibility` binds to a **bool**, never a string — a string bound to `Visibility` throws `E_INVALIDARG` (M2b).

**B5 — nothing about the user is stored or sent.** The check is a bare `GetStringAsync(url)`: no query string, no
identifying header, no body, no telemetry. Only the owner's URL and the skipped version are persisted.
## 3. PART C — applying it (bounded, and unexecuted)
**Desktop:** `DownloadAndVerifyAsync` downloads to a temp path and compares SHA256 against the manifest **before**
anything is launched. A mismatch deletes the file, returns no path, and yields a plain sentence. **A manifest with no
`sha256` is also refused** rather than trusted — my addition, since "verify the sha256" is meaningless if an absent hash
means "skip the check". `LaunchInstaller` is a separate private method reachable only after a true result.

**Phone:** `UpdateInstaller` uses `FileProvider.getUriForFile` → `ACTION_VIEW` with
`application/vnd.android.package-archive` + `FLAG_GRANT_READ_URI_PERMISSION`. Added `REQUEST_INSTALL_PACKAGES` to the
manifest and a `<cache-path name="updates">` to `file_paths.xml` (APKs stay in the app's cache, not external storage).
If `canRequestPackageInstalls()` is false it returns `NeedsPermission` with a plain sentence and an
`ACTION_MANAGE_UNKNOWN_APP_SOURCES` intent. **Android's own confirmation is not worked around**; `install()` refuses
outright when no manifest URL is set.

**🔴 THE INSTALL STEP IS UNEXECUTED.** No installer was launched on this PC and no APK handed to any phone — no phone was
reachable (see the beta gate). What ran: the decision, the gate, the fetch against a stub transport, and hash
verification against a temp fixture.

## 6. Manual test, once the backend exists (6 steps)
1. Serve a static `update.json` with the §2 shape; set `latest` above the installed version, `minimumSupported` below it,
   and a correct `sha256` for the file at `url`.
2. Paste the URL into **Settings → Updates** on the desktop. Restart Linc: the optional card should appear with the note.
   Click **Skip this version** — it goes away and stays away on the next restart.
3. Raise `latest` to a newer version. Restart: the card returns (the skip applied to that one version only).
4. Raise `minimumSupported` above the installed version. Restart: the **blocking** screen appears with no dismiss — then
   confirm the window still closes from the title bar and from the tray **Exit**.
5. Corrupt one character of `sha256` and click **Update**: Linc must refuse with a plain sentence and must **not** launch
   anything. Restore the hash and confirm Update then starts the installer.
6. Repeat 2 and 4 on the phone via **Settings → Updates**; on **Update**, confirm Android shows its own install prompt, and
   that with "install unknown apps" off you get the plain sentence and the settings shortcut instead.
