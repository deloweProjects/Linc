# PART C — the Phone section

The section is the **phone preview card** on Home (`HomePage.xaml`, widgets pane). M13f already made
`ConnectionCaption` its single statement of connection state; Part C fills the gaps.

- **C1 — owns connection state, plain language.** Name (`ModelName`), transport in use
  (`ConnectionCaption`: "Connected over USB" / "Connected over Wi-Fi" / "Connected directly — no
  ADB"). **New: link address** (`LinkAddress` / `HasLinkAddress`) shown only when it is meaningful —
  Direct TLS (whose peer **is** the phone, v18); on ADB the socket is a loopback forward and naming
  `127.0.0.1` would be a lie, so it stays null there and the line hides. No raw adb output.
- **C2 — resting and disconnected states.** Resting/connected: name + transport + address + battery +
  signal, full brightness. Disconnected: single calm line in the card ("Disconnected — the link is
  paused", i.e. the user-led Paused state resolved only by Resume; it does **not** claim auto-reconnect),
  while the M9d-1 offline banner owns the *cache* message ("showing what was last synced…") — the two
  say different things and are the two halves M13f settled. Nothing on Home duplicates the state.
- **C3 — scroll host from day one.** The card lives inside the widgets pane's `ScrollViewer`
  (`HomePage.xaml`, line 65) — expanded content is reachable (the M5a lesson pre-applied).
- **C4 — dynamic-island seam left.** The status area is exactly **one composable element** (the
  single `Border` card) whose entire state lives in `HomeViewModel` as its own properties
  (`ModelName`, `ConnectionCaption`, `LinkAddress`, `HasLinkAddress`, `BatteryText`, `SignalText`,
  gradient stops). No animation, no pill, no guessing. To build the island later, replace/extend this
  one card and its VM properties — nothing else on Home depends on its internals.
