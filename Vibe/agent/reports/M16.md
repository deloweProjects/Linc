## 1. PART A — resuming a paused PC player
### A1 — what the two rules gate on (the planner's premise is half wrong)
- **`BuildPayloadAsync`** (was `:193`): `if (session is null || !IsPlaying(session))` → try a
  **playing** Winamp-API player; then `if (session is null)` → any Winamp state, else `none:true`.
  **A non-null but PAUSED SMTC session falls through both guards and IS published**, with a real
  title and `playing:false`.
- **`OnCompanionMessage`** (was `:255-285`): `if (_session is { } s && IsPlaying(s))` → SMTC, **else
  `WinampRemote.Control(action)`**. A paused SMTC session reaches neither useful branch.

**Correction to the task file:** the payload has **no `present` field**. The phone
(`CompanionService.kt:148`) sets `present = false` **only** on `none: true`, which requires *no SMTC
session AND no Winamp player at all*. So a paused browser/PotPlayer/Spotify **is** published and the
phone's buttons are **enabled** — the press is merely routed to `WinampRemote` and dropped. There is
no mirror-image rule greying the buttons; **the entire defect is the routing branch.** The net effect
the task describes ("pause from the phone but never resume") is exactly right; the cause is one rule.

The hypothesis that `IsPlaying` is a *which-session* picker is **confirmed for `PickSession`**
(unchanged — it already prefers a playing session and falls back to `sessions[0]`). The `IsPlaying`
in the routing branch is a different, reachability gate, and that one is the bug.

### A2 — fix
`OnCompanionMessage` now routes on **the same rule `BuildPayloadAsync` publishes with**, so what the
phone sees is by construction what its buttons reach; a paused SMTC session is now the target. The
**`WinampRemote` fallback is kept** for "no SMTC session at all", playing or paused. No new message,
field or poll; `Envelope.Version` untouched.

### A3 — the pure static
New production file **`DESKTOP/Linc.Desktop/Services/PcMediaRouting.cs`**:
`PcMediaRouting.PickTarget(hasSmtcSession, smtcPlaying, hasWinamp, winampPlaying) -> PcMediaTarget
{None, Smtc, Winamp}` — four bools, no WinRT, no P/Invoke (D-036 posture). `PcMediaService` reduces
its live objects to those bools in one private helper; both call sites use it. **Harness:
`pccontrolsim`** — the fitting one, since it is already the pure-decision harness and its §1 P/Invoke
scan still passes with the new file compiled in. New **§7, 9 cases**, run with nothing playing here.
## 2. PART B — the Tools page
### B1 — the structure (task file half wrong here too)
Root is `Scaffold` → a **plain, non-scrollable `Column`** (`fillMaxSize`, insets, 24.dp horizontal).
Children: header `Row`; optional reason `Text`; `QuickControlsCard`, `MediaCard`, `PresentationCard`
(each `fillMaxWidth`, **no weight**); the trackpad `Card`; a 1.dp `AndroidView` IME sink. **Only the
trackpad carried `weight(1f)`** — not "everything shares `weight(1f)`". The consequence is worse than
described: the three cards take their natural height first and the trackpad absorbs **whatever is
left**, so every card M4c added came straight out of it.

### B2 — fix
- Root `Column` gets `.verticalScroll(rememberScrollState())`.
- Trackpad `Card`: `.weight(1f)` → **`.heightIn(min = 280.dp)`**. `weight` is illegal in a scrolling
  `Column` (unbounded height), so this is a swap, not an addition.
- **Why 280.dp:** roughly a third of a normal phone's content height, so the pad still reads as the
  page's main surface. It is a *gesture* surface needing room for a full-length drag and a two-finger
  scroll without the finger running off the edge, so the 48.dp touch-target minimum — which sizes a
  button — is the wrong yardstick. Below ~240 the drag distance starts costing cursor range.

### B3 — checks
Two tests added to `ToolsScreenSourceTest`: `.verticalScroll(rememberScrollState())` present, and
`.heightIn(min = 280.dp)` present **plus `.weight(1f)` absent**. **Stated plainly, as M4c did: these
are SOURCE-TEXT checks.** They prove the modifiers are written in `ToolsScreen.kt`; they do **not**
prove Compose lays the page out that way (no Robolectric or Compose rule in this module).
**§4.4 weakening declared:** the absence check pins `.weight(1f)` **with the leading dot** — my first
version matched bare `weight(1f)` and failed on my own explanatory comments. Prose in that file may
name `weight(1f)`; an applied modifier may not.
