## 2. What is wrong

**2.1 — Sync goes blank offline, same disease M9d-1 just cured on Home.** `SyncViewModel` never clears
on disconnect, so what is in memory survives — but nothing ever *loads* while disconnected, so a cold
start with no phone shows "Connect your phone to see messages." M9d-1 built the cure:
`LincStore`'s `sync_cache` methods and the `HomeCacheFormat` payload types. **Reuse them. Do not write
a second cache layer.**

**2.2 — A queued text lies about what it did.** The owner sent a text while disconnected and reported
it *"sends as if I'm connected — weird."* They are right. `SendReplyAsync` appends the message to the
conversation looking **identical to a sent one**; the only signal is a `LaneMessage` that is too quiet
to notice. M9c's queue works correctly — it just misrepresents itself. **This is the defect the owner
actually felt, and it is the more important half of this task.**

---

## 3. Decided design — implement exactly

**3.1 Sync reads cache when not connected.** On construction and on any transition **out of**
Connected, populate `Conversations` and `RecentCalls` from `sync_cache` for the active serial, using
the same kinds M9d-1 established: `"conversation"`, `"call"`. Live loads keep write-through as they do
on Home.

**3.2 The reply box stays usable offline.** `CanReply` must not gain an `IsConnected` term. With cached
conversations restored, a conversation is selectable offline, which is what makes M9c's queue reachable
at all. **This is the point of the whole feature — do not gate it.**

**3.3 A queued message is visibly distinct.** Add `IsPending` to the message view model. A message that
went to the outbox instead of the wire renders with a clear affordance: a "Queued" label and a muted
timestamp. **Do not rely on colour alone.** Follow existing text conventions; do not restyle the page.

**3.4 A pending message becomes normal when it actually sends.** When the outbox flush succeeds for a
row, the matching message in an open conversation flips to sent. `OutboxService` already knows the row
succeeded — surface it with an event the view model subscribes to. **If the conversation is not open,
do nothing** — no toast, no badge.

**3.5 The banner appears on Sync too**, with the same text and the same rule as Home: shown only when
disconnected **and** something was actually restored from cache. Reuse `HomeOfflineBanner.FormatText` —
do not write a second formatter.

**3.6 Never block or throw into the UI; never log a message body, address or number.** Standing rules.
