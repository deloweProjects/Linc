## 2. PART E — wallpaper: unblur it

The app shows the phone's wallpaper behind the widgets section. **Render it sharp.**

### 🔴 CORRECTION TO `M15.md` §5 — its premise was wrong
`M15.md` said *"no new plumbing, no new source — the same image, sharp."* **That is not what the code
does.** Master-read, three sites:
- `Services\ThemeSyncService.cs:22-23` — *"The phone's **pre-blurred** wallpaper thumbnail, or null when
  unavailable."*
- `ViewModels\HomeViewModel.cs:1624` — *"Tiny **pre-blurred** wallpaper thumbnail behind the widgets
  section."*
- `Services\ThemeSyncService.cs:158` — the bytes arrive via
  `connection.FetchBulkAsync("wallpaper", id, …)`.

**The blur and the size are produced on the phone**, by
`ANDROID/app/src/main/java/app/linc/android/service/WallpaperProvider.kt` (2,627 bytes — the master could
not open it, so this last step is an inference). **So this is a two-sided change.**

**E1 — Verify that before implementing.** Read `WallpaperProvider.kt` and the desktop's fetch path, and
report what each actually does: where the blur is applied, and what dimensions are sent.

**E2 — Send it sharp, within sane bounds.** Remove the blur and raise the resolution to something that
still belongs on a wire that also carries mirroring. **Choose a bounded maximum dimension, state the
number you chose and why, and measure the transfer size before and after.** A wallpaper is fetched on
every wallpaper change; a several-megabyte payload is not acceptable.

**E3 — No protocol change.** Same bulk kind (`wallpaper`), same message shapes, both constants stay at
**18**. **Mixed versions must keep working:** an old phone build against this desktop still sends the
small blurred image and the desktop must render it without complaint; a new phone against an older
desktop must not break either. Say how you satisfied this.

**E4 — The scrim.** The blur is very likely also acting as the scrim that keeps text legible, and the
theme is now black-and-white. Today the scrim is the `WallpaperScrimBrush` resource
(`Themes/MaterialExpressive.xaml`), applied at `Views\HomePage.xaml:62` and washed with the wallpaper's
dominant colour by `ApplyWallpaperAccent()` (`Services\ThemeSyncService.cs:266-274`).

**Expose the scrim's strength as a single named constant, default it to 0 (off, as the owner asked), and
tell the owner the constant's name and file** so it is a one-number change if text becomes hard to read.
**Do not silently leave a scrim on.**
