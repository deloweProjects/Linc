## 1. The bug, precisely located

The owner disconnected the phone and reported: *"whole app goes grey, most stuff can't even send,
especially on home, all stuff disappears, like I don't have a db for it."*

They are right, and there is a decision on record being broken — **D-032: the UI never blanks on
disconnect.** Three separate causes, all in `ViewModels/HomeViewModel.cs`:

**1.1 — Home actively empties itself.** `RefreshLaneWidgets()` at line ~1110:

```csharp
else            // not connected
{
    Photos.Clear();
    Conversations.Clear();
    Selected = null;
    RecentCalls.Clear();
    IncomingRinging = false;
}
```

**1.2 — the lane widgets are hard-gated on the link.** Lines ~1090–1092:
`public bool MessagesOn => IsConnected && _registry.SyncLane("messages")` and the same for
`CallsOn`. So even with data in hand, the panels turn themselves off.

**1.3 — everything dims to 55%.** `ContentOpacity => IsShowingCached ? 0.55 : 1.0` (line ~298), bound
at `Views\HomePage.xaml:375`. This is the "goes grey."

**And the store that should fix it already exists and has never been used.** M9a created the
`sync_cache` table — `(serial, kind, key, payload_json, updated_utc)`, primary key
`(serial, kind, key)` — and **nothing has ever written a row to it.** That is this session's job.

The **Apps** list is the one part that survives a disconnect, because M6c gave it its own per-device
file cache. Do **not** touch it, and do **not** migrate it into `sync_cache` — two cache layers for
one list is worse than the inconsistency. Apps is explicitly out of scope (§6).

## 2. Decided design — implement exactly

**2.1 Write-through on every successful load while connected.** Wherever Home currently populates
`Photos`, `Conversations` or `RecentCalls` from a live response, persist the same data to `sync_cache`
immediately afterwards. Kinds — use these literal strings: `"conversation"`, `"call"`, `"photo"`.
The `key` is the natural per-item identity (conversation address, call id, photo id). Upsert, so a
re-load replaces rather than duplicates.

**2.2 Read-through when not connected.** On construction and on any transition **out of** Connected,
populate those three lists from `sync_cache` for the active serial instead of clearing them. **Delete
the `else` branch's `Clear()` calls entirely** — replace, do not supplement.

**2.3 Ungate the lane widgets from the link.** `MessagesOn` and `CallsOn` become
`_registry.SyncLane("messages")` / `("calls")` with **no `IsConnected` term.** A lane the user turned
on stays on; what changes offline is where the rows come from, not whether the panel exists.

**2.4 No dimming. `ContentOpacity` returns `1.0` unconditionally** — keep the property (it is bound in
XAML and other things read it) but make it constant, and leave a comment saying the offline
affordance is now the banner, not opacity.

**2.5 One banner, at the top of the Home content grid.** Visible only when
`!IsConnected && <something was restored from cache>`. Text, plain language:
`"Phone disconnected — showing what was last synced at {time}."` The time is the **most recent**
`updated_utc` across the rows restored for that serial, rendered in local time, short format. If
nothing was restored, no banner — an empty Home with no phone ever paired must not claim to be
showing a cache.

**2.6 Cached rows are per device.** Everything keys off the active serial. Switching device shows that
device's cache, never a blend. A serial with no cached rows shows the existing empty-state text.

**2.7 Never block or throw into the UI.** Same stance as M9a/M9b/M9c: reads and writes are
fire-and-forget with a catch-all, and `LincStore` degrades rather than throwing. A corrupt or missing
DB means "no cache" — the page renders empty, exactly as today, never a crash.

**2.8 Never log message bodies, photo paths or call numbers.** `BRAIN.md`'s standing rule. Log the
kind and the row count. The `payload_json` on disk is fine; a log line is not.

**2.9 Retention: cap at 200 rows per (serial, kind), newest first.** Prune the excess after each
write-through. Without a cap this table grows forever, and unlike notification history there is no
user-facing retention control for it.

## 3. The work

1. **`Services/LincStore.cs`** — typed methods over `sync_cache`: upsert one row; list rows for
   (serial, kind) newest-first with a limit; prune beyond N per (serial, kind); count for a serial.
   Same lock + `TryOpen` + degrade pattern as the notification and outbox methods. Callable from a
   plain `net8.0` harness.
2. **`ViewModels/HomeViewModel.cs`** — the write-through (§2.1), the read-through replacing the
   `Clear()` branch (§2.2), the two ungated lane properties (§2.3), constant `ContentOpacity` (§2.4),
   and the banner's text + visibility properties (§2.5). **Put the banner text formatting in a pure
   static** (serial + a list of timestamps in, display string out) so the harness can call it.
3. **`Views/HomePage.xaml`** — the banner element at the top of the content grid, bound to those
   properties. Follow the existing card/text conventions; **do not restyle the page.**
4. **`tools/homecachesim`** — new plain `net8.0` harness, following `storesim`/`outboxsim` conventions
   exactly (numbered sections, `Check`/`CheckSub`, temp roots, exit 0/1, a `FindRepoRoot` handling both
   the `yellow/` and `Linc/` CWDs). Cover: upsert round-trip per kind; **re-upserting the same
   `(serial, kind, key)` replaces rather than duplicates**; newest-first ordering by `updated_utc`;
   per-serial isolation; the 200-row cap prunes the oldest and keeps the newest; the pure banner-text
   static with a known timestamp; and an empty cache yielding no banner.
   **Plus crude source-text checks that read the production files** and fail if the fix is reverted:
   `HomeViewModel.cs` contains **no** `Photos.Clear()` / `Conversations.Clear()` / `RecentCalls.Clear()`
   inside a `!IsConnected` branch, and `MessagesOn` / `CallsOn` do **not** contain `IsConnected`.
   Comment them as crude and say why.
