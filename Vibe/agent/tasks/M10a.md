## 2. Decided design

**2.1 This one legitimately uses ADB, and that is not a D-001 violation.** Installing a package is an
ADB capability with no protocol equivalent; the companion app cannot install another APK. `M2b` already
does exactly this to inject the companion — **reuse `PhoneSetupService`'s existing install primitive.
Do not write a second install path.**

**2.2 Entry point: an "Install app" action in the Device page's Tools card**, beside the existing
blocks. File picker, `.apk` only. Follow the card's existing conventions; **do not restyle the page.**

**2.3 Validate before touching the phone.** File exists, extension is `.apk`, non-zero length, and the
device is connected. Each failure is its own plain-language message — never raw adb output (D-009 is the
only place raw output is allowed, and this is not it).

**2.4 Progress is honest and staged.** `Validating` → `Copying to phone` → `Installing` → done or
failed. The UI must never sit on a frozen "Installing…" with no way to tell whether it died. Disable
the button while a run is in flight (one install at a time) and re-enable it in a `finally`.

**2.5 Failures are translated, not echoed.** Map at minimum: `INSTALL_FAILED_ALREADY_EXISTS` →
"That app is already installed."; `INSTALL_FAILED_INSUFFICIENT_STORAGE` → "Not enough space on the
phone."; `INSTALL_FAILED_INVALID_APK` / parse errors → "That file isn't a valid Android app.";
`INSTALL_FAILED_UPDATE_INCOMPATIBLE` → "A different version is already installed. Uninstall it first."
Anything unrecognised → "Install failed. The phone rejected the app." **Log the raw string; never show
it.** Put the mapping in a **pure static** so the harness calls it directly.

**2.6 The phone may prompt.** Some devices ask the user to confirm an ADB install. Say so in the UI
before starting: one line, "Check your phone — it may ask you to allow the install."

**2.7 Never block the UI thread and never throw into it.** Fire-and-forget with a catch-all, same
stance as M9.

## 3. The work

1. **`Services/PhoneSetupService.cs`** — expose the existing install primitive for an arbitrary local
   `.apk` path if it is not already reachable. **Smallest possible change.**
2. **`Services/ApkInstallResult.cs`** (new, dep-free) — the staged progress enum and the **pure static
   `TranslateInstallFailure(string raw)`** of §2.5. Must be compilable into a plain `net8.0` harness.
3. **`ViewModels/DeviceViewModel.cs`** — the command, validation (§2.3), staged status (§2.4), the
   in-flight guard, and the translated failure text.
4. **`Views/DevicePage.xaml`** — the "Install app" row in the Tools card + the status line + the §2.6
   hint. Nothing else.
5. **`tools/apkinstallsim`** — new harness, following `storesim`/`outboxsim`/`homecachesim`/
   `synccachesim` conventions exactly (numbered sections, `Check`/`CheckSub`, temp roots, exit 0/1,
   `FindRepoRoot` handling both CWDs). Cover: every §2.5 mapping including the unrecognised fallback;
   validation rejects a missing file, a non-`.apk` extension and a zero-byte file, each with a distinct
   message; and the staged progress order. **Plus crude source-text checks reading production files:**
   `DevicePage.xaml` binds the install command, and `DeviceViewModel.cs` contains the in-flight guard.
   Comment them as crude and say why.
