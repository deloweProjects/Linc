## 1. PART A — `Releases/update.json`, and the version scheme that would have broken it

### 🔴 A1 — the bug, found by the planner before it shipped
`UpdateDecision.parse` strips everything after `-`, so **`1.0.0-beta.1` and `1.0.0-beta.2` both parse
to `1.0.0`** — equal, decision `None`, and **no user would ever be told about beta.2.** Verify that
yourself first (run the parser on both strings and report what you get). **If it does not reproduce,
say so and skip A2.**

**A2 — Fix it by making the manifest's numbers four-part and numeric.** `latest` and
`minimumSupported` become `1.0.0.1`, `1.0.0.2`, … The parser already handles four parts, so **no
parsing rule changes.** The human-readable name (`1.0.0-beta.1`) stays in `notes` and in the release
title. **Document this convention in `Releases/RELEASE-NOTES.md`** in two lines: manifest versions are
numeric and ordered; display names are cosmetic.
**The installed version each app compares against must be the same numeric form** — check what
`InformationalVersion` / `versionName` actually feed into the check, and make them agree. **Say what
you found and what you changed.** A mismatch here is silent and total.

**A3 — Fill in the manifest.** The real asset URLs follow GitHub's fixed pattern:
```
https://github.com/deloweProjects/Linc/releases/download/v1.0.0-beta.1/Linc-Desktop-1.0.0-beta.1.zip
https://github.com/deloweProjects/Linc/releases/download/v1.0.0-beta.1/Linc-Companion-1.0.0-beta.1.apk
```
**Verify both with a HEAD request before writing them in** — expect 200 or a 302 to
`objects.githubusercontent.com`, with sizes **170,988,255** and **25,928,213**. **If either 404s,
report what you got and STOP; do not guess a URL.** Hashes come from `Releases/CHECKSUMS.txt` — copy
them, do not recompute.
**A4 —** `latest` and `minimumSupported` both `1.0.0.1`, so a current install decides **`None`**.
Prove it and paste the result.
**A5 —** Check the raw manifest URL the apps fetch:
`https://raw.githubusercontent.com/deloweProjects/Linc/main/Releases/update.json`
