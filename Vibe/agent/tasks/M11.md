# PART A — audio becomes an explicit, per-device mirror setting

## A2. Decided design

**A2.1 VERIFY EVERY FLAG IN THE VENDORED `cli.c` BEFORE USING IT**, and quote line numbers in the
report — the M7a/M9f precedent. A flag that exists upstream but not in this build fails at runtime, and
no harness would catch it. Flags this part needs: `--no-audio`, `--audio-codec`, `--audio-bit-rate`,
`--audio-source`. **If any is missing, stop and report it.**

**A2.2 The new fields go on the existing `MirrorSettings` record** (`Services/MirrorSettings.cs`),
persisted as `KnownDevice.Mirror`, per D-054 — **not** a new record, **not** on `KnownDevice` directly:

| field | type | default | why |
|---|---|---|---|
| `AudioEnabled` | `bool` | **`true`** | preserves today's behaviour exactly |
| `AudioBitRate` | `int` | `0` (= scrcpy default, flag omitted) | |
| `AudioSource` | `string?` | `null` (= scrcpy default, flag omitted) | `"output"` or `"mic"` only |

**A2.3 THE BYTE-IDENTITY RULE — this is the acceptance item most likely to catch a mistake.** A device
whose settings have never been touched **must produce a scrcpy command line byte-identical to today's.**
That means `AudioEnabled = true` emits **no audio flag at all** — not `--audio`, not anything. Only
`false` adds `--no-audio`; only a non-default bit rate or source adds its flag. **M5b's C1 check proved
this discipline for the video settings; do the same here.**

**A2.4 Validate, in the existing pure `ValidateSettingsFields`.** `AudioSource` must be `null`,
`"output"` or `"mic"`. `AudioBitRate` must be `0` or within a sane range (32_000–512_000). Reject
anything else in plain language — never raw scrcpy text.

**A2.5 UI in the existing "Mirror settings" expander** on the Device page's Tools card: a toggle for
audio, and the source + bit rate shown only when it is on. **Follow the existing controls; do not restyle
the card.** The preset combo stays a shortcut that writes into the record (D-054) — **do not add a
"Custom" entry.**

**A2.6 Say what it does in plain language.** One line under the toggle: audio plays through the PC while
mirroring, and the phone stays silent (that is scrcpy's normal behaviour — **verify it and describe what
you actually observe, do not assert it from the docs**).

# PART B — Desktop Mode can have audio, off by default

## B2. Decided design

**B2.1 `DesktopLaunchService.cs:101`'s hardcoded `--no-audio` becomes a setting.** New `AudioEnabled`
field on **`DesktopModeSettings`** (the existing per-device record), **default `false`** — Desktop Mode's
perf caps were tuned deliberately in M8c and audio is a real cost. **Default off preserves today's
behaviour exactly**, which is the same discipline as A2.3.

**B2.2 App windows keep `--no-audio`, unconditionally. Do not make it configurable.** Several windows can
be open at once and they must not fight over the audio stream. The comment at `AppLaunchService.cs:223`
already explains this — **leave it and leave the flag.** A harness check must fail if a future session
makes app-window audio configurable.

**B2.3 UI in the existing Desktop Mode settings expander**, with a plain-language note that audio costs
performance on the second screen. Follow the existing controls; do not restyle.

**B2.4 One audio consumer at a time is the honest limitation.** If the mirror is running with audio and
Desktop Mode starts with audio, **the second one may fail or take the stream** — scrcpy does not
arbitrate this. **Measure what actually happens** (launch both yourself; no phone needed to read the
argument construction, but if a phone is attached, observe the real behaviour) and **report it**. If it
is a real conflict, surface a plain-language warning when the user enables the second one. **Do not
build stream arbitration** — that is a milestone of its own.

## B3. The work

1. **`Services/DesktopModeSettings.cs`** — the field + default. **Grep the csprojs again** (§A3.1's rule
   applies identically — `DesktopModeSettings.cs` is one of the verbatim-compiled files).
2. **`Services/DesktopLaunchService.cs`** — honour the setting where `--no-audio` is currently hardcoded.
3. **`ViewModels/DesktopModeSettingsViewModel.cs`** + **`Views/DevicePage.xaml`** — the control.
4. **`tools/desktopsim`** — extend: default-off produces `--no-audio` byte-identically to today; enabling
   omits it; **plus a check that `AppLaunchService.BuildScrcpyArgs` still emits `--no-audio`
   unconditionally** (B2.2's guard, through the real pure static).
