# PART A — the new Linc mark, on both apps

**Source: `Assets/ico.png`** — a white rounded-corner **L** on a **solid black**
square. **It is outside the repo; copy it in, do not reference it from there.**

**A1. The transparency decision — read this before generating anything.** The source has **no alpha**;
the background is opaque black. That is correct for a square app icon and **wrong for two places**:

- **The Windows tray.** M12e loads `Assets/AppIcon.ico` into the tray. An opaque black tile reads well
  on Windows 11's dark taskbar and becomes a heavy black box on a light one.
- **Android adaptive icons**, which need a **transparent foreground** layer plus a separate background
  layer; a pre-baked black square gets masked and loses adaptive behaviour entirely.

**So produce two variants and say which went where:**
1. **`icon-square`** — the source as-is, opaque black. App icon, store/listing icon, `.ico`.
2. **`icon-mono`** — the **white L on transparency**, background removed. Tray icon and the Android
   adaptive **foreground** layer (with black as the adaptive **background** colour).

**Do not redraw the mark.** Same geometry, same proportions, same corner radius — only the background
changes.

**A2. Windows targets.** Regenerate `DESKTOP/Linc.Desktop/Assets/AppIcon.ico` as a **multi-size** `.ico`
(16/24/32/48/64/128/256). It is consumed in three places — **verify all three still work**:
- `Linc.Desktop.csproj`'s `<ApplicationIcon>` (exe icon);
- `MainWindow.xaml.cs`'s `AppWindow.SetIcon(... "AppIcon.ico")` (window/taskbar);
- **M12e's tray load** — `TrayIcon.Icon = new Icon(... "AppIcon.ico")` before `ForceCreate()`.
  **If the tray reads better from the mono variant, use it there and say so.**

Also refresh `Assets/linc.png`.

**A3. The mirror window icon.** `ToolLocator.FindScrcpyIcon()` resolves
`SCRCPY/Linc.scrcpy/bin/linc.ico` (and `SCRCPY/Linc.scrcpy/linc.ico`) — that is what brands the scrcpy
window via `SCRCPY_ICON_PATH`. **Replace it so the mirror matches.** **Do not change `ToolLocator`'s
lookup order, candidate count, or the six-level dev-tree depth** — that has been fixed twice and is
correct now. **Only the file contents change.**

**A4. Android.** Replace the launcher icons across every `res/mipmap-*` density **and** the adaptive
icon (foreground = mono, background = black). Check for a monochrome/themed-icon layer too; if the
manifest declares one, supply it.

**A5.** After Part A, **re-publish and confirm the bundle is intact** — 104 files in
`publish/SCRCPY/Linc.scrcpy/bin/` and `Linc.Desktop.pri` present. `packagesim`'s staleness guard means a

# PART B — black and white by default

**The app currently reads purple. The default must be neutral black-and-white.**

**B1. Find the central definition first, and report it.** The house resources are in
`DESKTOP/Linc.Desktop/Themes/` — `ExpressiveCard`, `FrostedCard`, `TitleText`, `BodyText`,
`ExpressiveTextBox`, `TonalButton` and friends. **Change the accent/brush definitions there.** Then
**grep every `Views/*.xaml` for hardcoded colour literals** and report each one you found — the
stragglers are the real work, and listing them is more useful than fixing them silently.

**B2. Neutral means neutral, not flat.** Keep a legible hierarchy: distinct surface / card / border /
text tones, and a visible focus and selection state. **A monochrome palette with no tonal separation is
a regression, not a redesign.** State the ramp you chose.

**B3. 🔴 DO NOT REINTRODUCE DIMMING.** D-032 and M9d-1 settled this: **offline shows full brightness
plus one banner — never dimming.** `ContentOpacity` is `1.0` deliberately (`HomeViewModel.cs`). If a
theme change touches opacity anywhere, say so explicitly and justify it.

**B4. Respect the existing card substitute.** `Border` has no `IsEnabled`, so the house pattern for an
inert card is dimming its **contents**, not the card. Do not "fix" that.

**B5. Contrast.** Body text on its surface should clear roughly **4.5:1**, large text and icons **3:1**.
State the ratios you landed on for the main text-on-surface pair. Black-and-white makes contrast
failures more likely, not less — a mid-grey on mid-grey is invisible.

**B6. Android too.** The phone app follows the same default. Match it; do not invent a second palette.

# PART C — the Phone section

M13f made `ConnectionCaption` the **single** statement of connection state and moved it here. Part C
makes this section worth looking at.

**C1. It owns connection state.** Device name, transport in use (USB / wireless ADB / Direct TLS),
and — where already available — the link's address. **Plain language only** (CONTRIBUTING.md): no raw
adb output, no jargon. "Connected over USB", not "transport_id:9".

**C2. Give it a clear resting state and a clear disconnected state.** Disconnected must read as calm and
explanatory, not as an error, and must not repeat itself anywhere else on Home.

**C3. Scroll host from day one.** Every new page or section gets one — M5a's lesson, learned when the
Device page had none and expanded content became unreachable.

**C4. 🚧 The "dynamic island" behaviour is NOT in this task.** The owner wants a live status surface —
something that expands on activity — as the **next** piece of work, and its shape is still an open
design question. **Build the section so that is easy to add later: keep the status area a single
composable element with its own view-model state.** Do not animate, do not build a pill, do not guess at
it. **Report how you left the seam.**
