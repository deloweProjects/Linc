## 1. PART A — the phone cannot resume a paused PC player

**Found by M4c and correctly left alone then; it is in scope now.** `Services/PcMediaService.cs`
routes `pc.media.control` to the SMTC session **only when `IsPlaying(session)`** — so a paused
player (a video paused in a browser, PotPlayer, Spotify) is unreachable, and `BuildPayloadAsync`'s
mirror-image rule makes the PC publish `present: false`, so the phone correctly greys the buttons.
**Net effect: you can pause from the phone but never resume.** Same on Home's media widget.

**A1 — Read both rules first** (`PcMediaService.cs` around `:193` and `:255-285`) and report what
each actually gates on. **Planner's hypothesis, verify it:** the `IsPlaying` filter exists to pick
*which* of several registered sessions the phone is showing, not to decide reachability — so the fix
is to prefer the playing session but **fall back to the current SMTC session when none is playing**,
rather than dropping through to `WinampRemote`.

**A2 — Make paused players reachable.** `present` should be true when there is *any* usable session,
and `play` must reach it. **Keep the `WinampRemote` fallback for when there is no SMTC session at
all.** Do not add a new message, a new field, or a poll.

**A3 — Put the choice in a pure static** (e.g. `PcMediaRouting.PickSession(...)` or similar,
harness-linkable with no WinRT types — the D-036 pattern) so `pccontrolsim` (or the nearest fitting
harness — say which) proves the selection rule with no media playing.

**Out of scope in this part:** album art, position/seek, per-app routing, anything on the wire.

than compressing it.
