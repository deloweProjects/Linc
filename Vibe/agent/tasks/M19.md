## 3. PART C — the update channel lives in this repo

**Replace M17b's settings-URL design.** The owner's ask: *"embed this repo and create a mechanism such
that committing a certain file, when changed, triggers an update on all builds — optional or forced —
and a setting, initially ON, that a user can turn off to update manually."*

**C1 — `Releases/update.json` is the channel.** Both apps read it from the repo's raw URL, **baked in
at build time as a constant, not a user setting**:
`https://raw.githubusercontent.com/deloweProjects/Linc/main/Releases/update.json`
Shape (document it in the file's own comment block *and* in `Releases/RELEASE-NOTES.md`):
```json
{
  "latest": "1.0.0-beta.2",
  "minimumSupported": "1.0.0-beta.1",
  "notes": "One short line shown to the user.",
  "desktop": { "url": "https://github.com/deloweProjects/Linc/releases/download/v1.0.0-beta.2/Linc-Desktop-1.0.0-beta.2.zip", "sha256": "..." },
  "android": { "url": "https://github.com/deloweProjects/Linc/releases/download/v1.0.0-beta.2/Linc-Companion-1.0.0-beta.2.apk", "sha256": "..." }
}
```
**Editing that one file and committing it is the whole release mechanism.** Raising `minimumSupported`
turns an optional update into a forced one for everyone below it. Say that in the docs, in one line.

**C2 — Keep M17b's `UpdateDecision` rule exactly as it is** — it is already tested and its negative
proofs exist. **Only the source of the manifest changes.** Both constants stay at 18; this touches no
protocol.

**C3 — Strip the update plumbing out of the UI.** The manifest-URL text box goes. What remains:
- **One setting, "Keep Linc up to date", default ON.** Off = no checks at all, ever; the app says
  where to get updates manually (the Releases page) and nothing else.
- **A "Check now" button** that is only useful when the setting is on.
- The optional-update card and the forced-update screen from M17b stay as built.
**C4 — Safety, because a bad `update.json` can now reach every user.** Unreachable, malformed, or
unparseable manifest → **treat as no update**, log at Debug, never a user-facing error. A hash
mismatch → **refuse to run the download and say so**. **Add a harness check that a manifest with
garbage in every field yields `None`.**
**C5 — Seed `Releases/update.json` with the CURRENT version as `latest` and `minimumSupported`**, so
nothing ever prompts until the owner deliberately bumps it. Prove that: with the seeded file, the
decision is `None`.
