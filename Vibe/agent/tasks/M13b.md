## 2. What to implement

**`Vibe/agent/opencode-docs/PROTOCOL.md` → "v18 — Instant ADB link-up over a hotspot" is already
written. Read it and implement exactly that.** Do not edit it; if it is wrong, say so in the report.

Four messages: `adb.announce`, `adb.down` (phone → desktop), `adb.arm`, `adb.ack` (desktop → phone).

### 2.1 The generation counter — build this FIRST, before anything consumes a message

Monotonic, incremented on every link event, carried on all four messages. **The desktop discards any
message whose `gen` is lower than the highest seen.**

**Why it comes first:** without it, a role flip in flight (phone-AP → PC-AP) lets a stale announcement
from the old topology arrive after the new one and point ADB at a dead address. That failure is
intermittent, and it is the single most expensive bug in this design. **Pure static:
`ShouldAccept(incomingGen, highestSeenGen) → bool`,** harness-tested, so the rule is provable without a
network.

### 2.2 Phone side: know your own adbd state

In cost order, **stop at the first success**, and treat a miss as "try next", never as "adbd is down":

1. **System properties** (~1 ms): `service.adb.tls.port`, then `service.adb.tcp.port`, then
   `persist.adb.tcp.port`. Read via `SystemProperties.get()` by reflection or a `getprop` subprocess.
   **Not populated on every OEM build.**
2. **`NsdManager` self-discovery** (~100–300 ms): browse `_adb-tls-connect._tcp` (wireless debugging,
   carries the random port), `_adb._tcp` (legacy tcpip), `_adb-tls-pairing._tcp` (pairing open, not yet
   paired). **Match the resolved service against your own interface addresses** so you do not pick up a
   second device on the same hotspot.
3. **Loopback scan, last resort** (~200 ms): `adbd` binds `0.0.0.0` so it answers on `127.0.0.1`.
   Sweep `5555` plus the ephemeral range. **Bound the thread count and total wall time, and run it off
   the main thread** — an unbounded 200-thread sweep on a phone is an ANR and battery complaint waiting
   to happen. **If you cannot make it cheap, ship methods 1–2 and report that method 3 is deferred;**
   that is a better outcome than a janky app.

### 2.3 The liveness gate — mandatory, and the highest-value check in the design

Whichever method found the port, **the phone confirms adbd is actually accepting via a loopback connect
(≈200 ms timeout) before announcing.** Set `verified: true` only then.

**Never announce a port you have not just connected to.** The L3 link comes up **before** adbd has
re-bound to the new interface, so link-up is not readiness. **The desktop must refuse to act on
`verified: false`.**

### 2.4 Desktop side

- Consume `adb.announce` → resolve via M13a's `SelectEndpoint` (**the same-subnet filter still applies
  to `addrs`**) → `adb disconnect` → `adb connect` → verify state **and serial**.
- Send `adb.ack` with the outcome so the phone stops retrying and logs honestly.
- `unauthorized` on a TLS port → **route to pairing, do not retry.** `offline` → disconnect, retry once.
- `adb.arm` is sent when the desktop wants a re-arm; **in this task it may be a no-op on the phone side
  beyond re-running 2.2–2.3.** Actual arming is M13c.
