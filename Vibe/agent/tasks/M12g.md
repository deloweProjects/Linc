## 1. Why this task exists — M12f found a planner error that would have damaged the owner's store

M12f's Part A was specified by me to sandbox the published app by **redirecting the `LOCALAPPDATA`
environment variable** at a temp root. **That does not work, and the agent proved it and refused to run
the launch half rather than proceed.**

`Environment.GetFolderPath(SpecialFolder.LocalApplicationData)` resolves through the Windows known-folder
API, **not** through the `LOCALAPPDATA` environment variable. `DeviceRegistry.DefaultRootPath`
(`DeviceRegistry.cs:213`) is built from exactly that call. So a child process launched with a redirected
`LOCALAPPDATA` would have read and written **the owner's real `%LOCALAPPDATA%\Linc\`** — `settings.json`,
`linc.db`, `tls-identity.pfx`, `cache/`, `logs/`.

**That is the third time this project has nearly or actually destroyed the owner's real store** (M2a's
killed `devicesim`, M6b's `homelayoutsim` sections 5–6, and now this). It did not happen this time
**only because the agent probed the assumption at runtime, found it false, and turned the check into a
loud SKIP instead of a silent unsafe launch.** That is the behaviour this project exists to produce.
**Do not undo that safety probe in this task — keep it as the guard it is.**

**The architecture already has the right answer and has since H1/D-057.** `DeviceRegistry(string?
rootPath = null)` takes an injected root, and every other store takes its root from
`IDeviceRegistry.RootPath` — `LincStore` and `AppCatalog` are wired that way at `App.xaml.cs:70` and
`:77`. **The only thing missing is a way to set that root from outside the process.** That is Part A.

# PART A — the `--data-root` switch

## A1. Parsing

Add a **pure static** so a harness can test it without launching anything. Put it beside the M12e
`--startup` parsing if that is already in `Services/StartupRegistration.cs`; otherwise create
`Services/CommandLineOptions.cs`. **Do not scatter command-line parsing across two files** — report where
you put it and why.

`static string? ParseDataRoot(IEnumerable<string> args)`:

- Accepts **both** `--data-root <path>` (two tokens) and `--data-root=<path>` (one token).
- Returns `null` when the switch is absent, when its value is missing, or when the value is
  empty/whitespace. **A malformed switch must fall back to the default root, never to a half-parsed
  path.**
- **Resolves the result to an absolute path** (`Path.GetFullPath`). A relative root would scatter stores
  relative to the working directory, which differs between a shortcut, a Run-key launch and a harness.
- Case-insensitive on the switch name.

## A2. Wiring

`App.xaml.cs:37` currently reads `.AddSingleton<IDeviceRegistry, DeviceRegistry>()`. Change it to a
factory registration that constructs `new DeviceRegistry(parsedRoot)` — where `parsedRoot` is
`ParseDataRoot(Environment.GetCommandLineArgs())`, i.e. **`null` in every normal launch**, so production
behaviour is byte-for-byte unchanged.

- Read the command line from `Environment.GetCommandLineArgs()`, **not** from `LaunchActivatedEventArgs`
  (unpackaged app — the args do not arrive there).
- **Nothing else changes.** `LincStore` and `AppCatalog` already take their root from
  `IDeviceRegistry.RootPath`; they must keep doing so. **If you find any other store calling
  `Environment.GetFolderPath` directly, report it — do not fix it in this task.**

## A3. Make a non-default root visible

When `parsedRoot` is not null, **log it at `Info` at startup**: the store root in use. A redirected data
root must never be silent — a future session debugging "my devices vanished" needs that line. This is the
same reasoning as D-057's guard.

## A4. One hazard to close explicitly

M12e's `StartupRegistration.BuildRunCommand` writes the Run-key command line. **It must never emit
`--data-root`.** A Run key pinned to a temp path would point the owner's real startup launch at a store
that gets deleted. **Add an assertion to `autostartsim`** that `BuildRunCommand`'s output contains
`--startup` and does **not** contain `--data-root`. If M12e has not landed yet, say so and skip this
item explicitly rather than inventing it.
