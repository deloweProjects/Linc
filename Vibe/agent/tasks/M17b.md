## 1. PART A — the decision, as a pure static on BOTH sides

**The whole feature is one rule, and it must be provable with no network.**

```
UpdateDecision Decide(installedVersion, manifestLatest, manifestMinimumSupported, userSkipped)
  -> None | Optional | Forced
```
- **Forced** when `installed < minimumSupported`. **Forced ignores `userSkipped` — always.**
- **Optional** when `installed < latest` and not forced and the user has not skipped *that exact
  version*.
- **None** otherwise.
- **Version comparison is semantic, not string** — `1.10.0 > 1.9.0`. Malformed or missing input →
  **None**, never Forced. A backend typo must never brick the app.

Implement it **twice** — `DESKTOP/Linc.Desktop/Services/UpdateDecision.cs` (harness-linkable, no WinUI
types, D-036 posture) and an equivalent pure Kotlin object — and **test both**: a new
`tools/updatesim` (or the nearest fitting harness — say which and why) plus Android unit tests.
**Cover: equal versions, older latest than installed, missing fields, garbage strings, skip honoured
for Optional, skip IGNORED for Forced.**

## 2. PART B — fetch, store, and show it

**B1 — The manifest.** Define the JSON shape in your report **and** in a code comment, so the owner
can build the backend against it. Suggested, keep it minimal:
```json
{ "latest": "1.2.0", "minimumSupported": "1.1.0", "url": "https://…/Linc-1.2.0.exe",
  "notes": "one short line", "sha256": "…" }
```
**B2 — Where the URL lives.** A setting on each side, **empty by default**, with the whole feature
**inert while empty** — no requests, no UI, nothing in the logs. The owner turns it on by pasting a
URL. Desktop: the existing settings record + Settings page. Phone: `SettingsScreen.kt`.
**B3 — When it checks.** On app start (after the UI is up, never blocking it) and no more than once
every 6 hours. **One in-flight request at a time**; failures are silent except a debug log line — a
dead backend must never produce a user-facing error.
**B4 — What the user sees**, using M17a's design system on the phone and M14's on the desktop:
- **Optional:** a dismissible card — version, the one-line note, *Update* and *Skip this version*.
  Skipping records **that version only**, so the next release asks again.
- **Forced:** a **blocking** screen that cannot be dismissed — one sentence explaining why, and the
  *Update* button. **The app must remain closable** (no trapping the user in a window they cannot
  exit); block the app's function, not the process.
**B5 — Never store or send anything about the user.** The check is a plain GET of a static file.

## 3. PART C — actually applying it (bounded, honestly)

**Desktop:** download to a temp path, **verify the sha256 from the manifest**, then launch the
installer and exit. **If the hash does not match, refuse and say so** — never run an unverified
binary. Do not build a differential updater, a service, or a restart supervisor.
**Phone:** download the APK and hand it to the system package installer via `ACTION_VIEW` /
`FileProvider` with `REQUEST_INSTALL_PACKAGES`. **Android will show its own confirmation — that is
correct and must not be worked around.** If the permission is not granted, say so in plain language
and offer the settings intent.
**Both:** with no manifest URL set, none of this code path can execute. Prove that.

**Do not test-run a real update on the owner's machine or phone.** Point the setting at a
`file:///`-style or localhost fixture you create in a temp folder, exercise the decision and the
fetch, and **stop before actually installing anything**. Say plainly that the install step is
unexecuted.
